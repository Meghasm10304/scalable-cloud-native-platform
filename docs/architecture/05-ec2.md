# Stage 4: AWS Compute (EC2) Deployment

## 🎯 Goal
Deploy the CineSangeet application on an EC2 instance to verify it runs in a cloud environment before introducing load balancing or containers.

## 🧠 What I Learned
- How to launch an EC2 instance in a specific VPC subnet.
- Why we used the `web` security group for initial testing vs. the `app` security group for production.
- How to use PM2 to keep Node.js processes alive after SSH disconnects.
- How to import existing manual infrastructure into Terraform state using `terraform import`.
- How to attach an IAM Instance Profile to an EC2 instance using Terraform (`iam_instance_profile`).
- How to fetch secrets from AWS Secrets Manager using the AWS SDK at runtime (zero static credentials).

## 🛠️ Tools & Services
- **AWS:** EC2, Security Groups, IAM Instance Profile, Secrets Manager.
- **OS:** Ubuntu Server 26.04 LTS.
- **Runtime:** Node.js v20, npm.
- **Process Manager:** PM2.
- **IaC:** Terraform.

## 📦 Artifacts Created
- `infrastructure/compute/main.tf`: Defines the EC2 instance, Secrets Manager secret, and IAM policy.
- `infrastructure/compute/variables.tf`: Configurable parameters (AMI, key name, env).
- `infrastructure/compute/outputs.tf`: Exposes Public IP for easy retrieval.
- **Live Resource:** EC2 Instance `i-0dcaa411a08917d81`.

## 🔧 Implementation Steps

### 1. Manual Provisioning (Learning Phase)
I first launched the instance via the AWS Console to understand the UI options:
- Selected `t3.micro` (Free Tier).
- Placed in `app-vpc-public-a` subnet.
- Attached `web` security group.
- Enabled "Auto-assign public IP".

### 2. Application Setup
Connected via SSH (`ubuntu@<IP>`) and ran:
```bash
sudo apt update && sudo apt install -y nodejs git
# Upgraded to Node 20 LTS
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
git clone <repo-url>
cd scalable-cloud-native-platform
npm install
pm2 start server.js --name cine-app 
```

### Secrets Manager Integration
```text
Instead of using .env files, I created a secret in AWS Secrets Manager and attached an IAM policy to the EC2 instance role.
```
## Terraform Resources Created:
```text
aws_secretsmanager_secret.app_config: Stores TMDB_API_KEY and LASTFM_KEY.
aws_iam_role_policy.app_instance_secrets: Allows the EC2 role to read the secret.
aws_instance.cinesangeet_server: Updated with iam_instance_profile to attach the role.
App Behavior: The server.js uses @aws-sdk/client-secrets-manager to fetch credentials at startup. No static keys exist on disk.
```
